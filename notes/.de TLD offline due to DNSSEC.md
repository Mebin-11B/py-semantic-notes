- **A record** `nic.de. 3600 IN A 81.91.170.12` with an RRSIG (type A, signed by ZSK, same validity window).
- **NS records** (ns1–ns4.denic.*) with an RRSIG (type NS, signed by ZSK, same validity window).
- **SOA record** (`ns1.denic.de.` primary, `dns-operations.denic.de.` contact, serial 1778019826, refresh 10800 s, retry 1800 s, expire 3600000 s, minimum 1800 s) with an RRSIG (type SOA, signed by ZSK).

All responses include EDNS0 (UDP size 1452) and indicate DNSSEC OK (`do = 1`). No errors were reported (RCODE 0, AA = 1).

## Discussion Summary
Comments converge on a DNSSEC validation failure in the .de TLD, traced to a malformed NSEC3 signature during a ZSK rollover, causing validating resolvers to return SERVFAIL and rendering many German‑registered sites unreachable. Users report widespread access problems, stress, and business impact, while others analyze the technical cause, note temporary mitigations (e.g., disabling DNSSEC validation or using insecure settings), and criticize DNSSEC’s centralised risk and lack of robust disaster‑recovery testing. Humor and speculation appear alongside calls for better fallback planning.
